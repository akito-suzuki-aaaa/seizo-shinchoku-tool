# 製造進捗管理ツール（プロトタイプ）

製造業の進捗を、社員がスマホで記録 → 社内データベースに時系列で蓄積 → 日報・報告書化 → 顧客がログインして閲覧、という流れを実現するWebツールです。

## 構成

| 画面 | ファイル | 用途 |
|---|---|---|
| 入口 | `index.html` | 3画面へのリンク・デモ操作 |
| 社員用 | `employee.html` | スマホから進捗・写真を記録 |
| 社内管理 | `admin.html` | 全案件の一覧・履歴・日報/報告書生成 |
| お客様用 | `customer.html` | ログインして自社案件を閲覧（閲覧のみ） |
| データ層 | `store.js` | デモ(localStorage)／本番(GAS)を切替 |
| デザイン | `styles.css` | 共通スタイル |
| バックエンド | `gas/Code.gs` | 本番用のGAS API |

## まず動かす（デモモード・設定不要）

`index.html` をブラウザで開くだけ。同じブラウザ内で3画面がデータを共有します。

- お客様ログイン（デモ）: ID `a-sha` / パスワード `1234`（A社）
- 写真は自動で縮小してブラウザ内に保存されます。
- 「デモデータを初期化」でサンプルの初期状態に戻せます。

> ローカルでファイルを直接開くと一部ブラウザで動かない場合があります。その際は簡易サーバーで開いてください（例）:
> ```bash
> python -m http.server 8000
> ```
> → http://localhost:8000/index.html

## スマホ実機でテストする

### 方法A：同じWi-Fiで開く（すぐ試せる・アカウント不要）

1. `スマホでテスト_起動.bat` をダブルクリックしてサーバーを起動する。
2. 画面に表示される `http://（PCのIP）:8123/index.html` を、
   **PCと同じWi-Fiにつないだスマホ**のブラウザで開く。
   - このPCのIP例：`http://129.1.0.26:8123/index.html`
3. 初回はWindowsのファイアウォール確認が出るので「アクセスを許可する」を選ぶ。

> 会社のWi-Fiによっては端末同士の通信が遮断されている場合があります。
> その場合は方法B（GitHub Pages）を使ってください。

### 方法B：GitHub Pagesで公開する（どこからでも・おすすめ）

このフォルダをGitHubに置き、Pagesで公開すると、社外の顧客も含めて
どのスマホからでもURLでアクセスできます（既存の勤怠ツールと同じ手順）。
スマホ実機テストとしても、社内外どこでも開けるこの方法が最も確実です。

## 本番モードにする（スプレッドシートに保存）

1. Google スプレッドシートを新規作成する。
2. 拡張機能 → Apps Script を開き、`gas/Code.gs` の中身を貼り付けて保存。
3. エディタで関数 `setup` を一度実行する（シートとサンプルデータが自動作成される。初回は権限承認あり）。
4. デプロイ → 新しいデプロイ → 種類「ウェブアプリ」
   - 実行するユーザー: **自分**
   - アクセスできるユーザー: **全員**
5. 発行された **ウェブアプリURL** をコピー。
6. `store.js` の先頭 `const GAS_URL = "";` にそのURLを貼る。
7. `index.html` を開くと「デモ」表示が消え、データはスプレッドシートに保存される。

写真は Drive のフォルダ「進捗管理_写真」に保存され、リンクがシートに記録されます。

## GitHub Pages で公開する

このフォルダを GitHub リポジトリに置き、Settings → Pages で公開ブランチを指定するだけで、社員・顧客がURLからアクセスできます（既存の勤怠ツールと同じ手順）。

## セキュリティについて（重要）

このプロトタイプの顧客ログインは簡易版です。本運用の前に:

- `gas/Code.gs` でパスワードを**ハッシュ化して保存**する（現状は平文）。
- ログイン後の**トークン発行**で認証を維持する。
- 図面など機密性の高いデータを扱う場合は、本格的な認証基盤への差し替えを検討する。

## データ構造（スプレッドシートのシート）

- `customers` … 顧客ログイン情報（id, company, loginId, password）
- `projects` … 案件（id, name, customerId, customerName, owner, startDate, dueDate, status）
- `processes` … 工程（id, projectId, name, order, targetQty）
- `logs` … ★時系列の進捗記録（id, projectId, processId, datetime, author, progress, status, qty, comment, photo）

`logs` に1行ずつ追記される仕組みが、そのまま「時系列の履歴」と「日報・報告書の元データ」になります。
